# 项目考勤时间接口文档

## 基本信息
- 基础路径: `/projectAttendance`
- 描述: 项目考勤时间管理接口
- Controller: ProjectAttendanceController

## 接口列表

### 1. 获取考勤时间详情

**接口地址**: `POST /projectAttendance/get/{id}`

**接口描述**: 根据ID获取考勤时间详情

**路径参数**:

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| id | String | 是 | 考勤时间ID |

**响应示例**:
```json
{
  "code": 200,
  "data": {
    "id": "123456",
    "projectId": "proj001",
    "start": "08:30:00",
    "end": "12:00:00",
    "type": 1,
    "createdAt": "2024-01-01T00:00:00Z",
    "updatedAt": "2024-01-01T00:00:00Z"
  },
  "message": "success"
}
```

### 3. 批量更新考勤时间

**接口地址**: `POST /projectAttendance/update`

**接口描述**: 一次性设置项目的上午和下午考勤时间，支持同时设置或只设置其中一个时间段。系统会根据项目ID自动判断是创建还是更新。

**业务规则**:
- projectId 和 type 唯一确定一条考勤记录
- 可以同时设置上午和下午考勤时间
- 可以只设置上午或只设置下午
- 如果该组合已存在，则更新现有记录
- 如果该组合不存在，则创建新记录

**请求参数**:

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| projectId | String | 是 | 项目ID |
| morningStart | String | 否 | 上午开始时间（格式：HH:mm:ss） |
| morningEnd | String | 否 | 上午结束时间（格式：HH:mm:ss） |
| afternoonStart | String | 否 | 下午开始时间（格式：HH:mm:ss） |
| afternoonEnd | String | 否 | 下午结束时间（格式：HH:mm:ss） |

**请求示例 - 同时设置上午和下午**:
```json
{
  "projectId": "1",
  "morningStart": "08:30:00",
  "morningEnd": "12:00:00",
  "afternoonStart": "14:00:00",
  "afternoonEnd": "17:30:00"
}
```

**请求示例 - 只设置上午**:
```json
{
  "projectId": "1",
  "morningStart": "08:30:00",
  "morningEnd": "12:00:00"
}
```

**请求示例 - 只设置下午**:
```json
{
  "projectId": "1",
  "afternoonStart": "14:00:00",
  "afternoonEnd": "17:30:00"
}
```

**响应示例**:
```json
{
  "code": 200,
  "data": {
    "morningId": "123456",
    "afternoonId": "123457"
  },
  "message": "success"
}
```

**响应说明**:
- data 是一个对象，包含 morningId 和 afternoonId
- morningId: 上午考勤记录的ID（如果设置了上午考勤）
- afternoonId: 下午考勤记录的ID（如果设置了下午考勤）
- 如果只设置了一个时间段，则只返回对应的ID

## 业务逻辑说明

### 唯一性约束
- **projectId + type** 组合唯一确定一条考勤记录
- 一个项目只能有一个上午考勤时间（type = 1）
- 一个项目只能有一个下午考勤时间（type = 2）

### 批量更新机制
当调用 `/projectAttendance/update` 接口时：
1. 接口支持同时设置上午和下午考勤，也支持只设置其中一个
2. 对于上午考勤：
   - 如果 morningStart 和 morningEnd 都有值，则处理上午考勤
   - 系统根据 projectId 和 type=1 查询是否存在上午记录
   - 存在则更新，不存在则创建
3. 对于下午考勤：
   - 如果 afternoonStart 和 afternoonEnd 都有值，则处理下午考勤
   - 系统根据 projectId 和 type=2 查询是否存在下午记录
   - 存在则更新，不存在则创建
4. 返回包含 morningId 和 afternoonId 的对象

### 使用建议
- **批量设置**: 推荐一次性设置上午和下午，减少接口调用
- **单独修改**: 只需要修改上午或下午时，只传对应的字段即可
- **前端简化**: 无需判断是创建还是更新，系统自动处理
- **ID管理**: 返回的ID可用于后续的删除操作

## 注意事项

1. **时间格式**：所有时间字段使用标准时间格式 HH:mm:ss
2. **type字段**：系统自动处理，上午为1，下午为2
3. **唯一性约束**：projectId 和 type 组合唯一，一个项目一个时间段只能有一个考勤
4. **必填字段**：projectId 必填，至少提供一组时间段（上午或下午）
5. **时间段完整性**：如果要设置上午，morningStart 和 morningEnd 必须同时提供；下午同理
6. **逻辑删除**：删除操作为逻辑删除，不会物理删除数据
7. **排序规则**：查询结果按 type 和 start 排序
8. **项目关联**：每条考勤记录必须关联一个项目

## 数据库约束建议

为了确保数据一致性，建议在数据库层面添加唯一索引：

```sql
CREATE UNIQUE INDEX idx_project_attendance_unique
ON business_project_attendance (project_id, type)
WHERE deleted_at IS NULL;
```
