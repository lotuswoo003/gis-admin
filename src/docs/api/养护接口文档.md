# 养护接口文档

## 基本信息
- 基础路径: `/conserve`
- 描述: 养护管理接口
- Controller: ConserveController

## 接口列表

### 1. 获取养护详情

**接口地址**: `POST /conserve/get/{id}`

**接口描述**: 根据ID获取养护详情

**路径参数**:

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| id | String | 是 | 养护ID |

**响应示例**:
```json
{
  "code": 200,
  "data": {
    "id": "123456",
    "code": "YH001",
    "name": "草坪养护",
    "mode": "grassland",
    "parentId": 0,
    "organizationId": 1001,
    "dispalyOrder": 1,
    "json": "{\"key\":\"value\"}",
    "versionId": 1,
    "securityJson": "{\"safety\":\"check\"}",
    "createdAt": "2024-01-01T00:00:00Z",
    "updatedAt": "2024-01-01T00:00:00Z"
  },
  "message": "success"
}
```

### 6. 分页查询养护

**接口地址**: `POST /conserve/page`

**接口描述**: 支持按编码、名称、类型、父ID、组织ID、版本ID过滤

**请求参数**:

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| page | Integer | 是 | 页码，从1开始 |
| rows | Integer | 是 | 每页数量 |
| code | String | 否 | 编码（精确匹配） |
| name | String | 否 | 名称（模糊查询） |
| mode | String | 否 | 类型（精确匹配） |
| parentId | Long | 否 | 父ID（精确匹配） |
| organizationId | Long | 否 | 组织ID（精确匹配） |
| versionId | Long | 否 | 版本ID（精确匹配） |

**请求示例 - 按组织ID查询**:
```json
{
  "page": 1,
  "rows": 10,
  "organizationId": 1001
}
```

```json
{

  "rows": 10,
  "mode": "grassland",
  "name": "草坪"
```

```json

  "page": 1,

  "parentId": 0
```

```json
        "mode": "grassland",
        "parentId": 0,
        "organizationId": 1001,
        "dispalyOrder": 1,
        "json": "{\"key\":\"value\"}",
        "versionId": 1,
        "securityJson": "{\"safety\":\"check\"}",
        "createdAt": "2024-01-01T00:00:00Z",
        "updatedAt": "2024-01-01T00:00:00Z"
```

## 业务逻辑说明

### 树形结构
- 养护项支持父子层级结构
- parentId = 0 或 null 表示顶级节点
- 可以通过 parentId 构建树形菜单

### 组织隔离
- 每个养护项必须关联一个组织
- 不同组织的养护项相互独立
- 支持按 organizationId 过滤数据

### 版本管理
- versionId 用于标识不同版本的养护配置
- 支持版本回滚和版本对比

### 排序规则
- 查询结果按 dispalyOrder 升序排列
- 相同 dispalyOrder 按 updated_at 倒序排列

### organizationId 默认值回退
- 当指定 organizationId 查询无数据时
- 自动使用 organizationId = -1 查询默认配置
- 实现组织级配置和默认配置的回退机制

## 注意事项

1. **name 和 mode 必填**：创建养护项时必须提供名称和类型
2. **organizationId 必填**：每个养护项必须关联组织
3. **逻辑删除**：删除操作为逻辑删除，不会物理删除数据
4. **JSON字段**：json 和 securityJson 字段存储JSON格式字符串
5. **模糊查询**：仅 name 字段支持模糊查询，其他字段均为精确匹配
6. **树形结构**：注意维护 parentId 的正确性，避免循环引用
7. **默认配置**：organizationId = -1 的数据作为默认配置
